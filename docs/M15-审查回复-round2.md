# M15 审查回复 Round 2（已被独立员工模型取代）

> 本文件记录的“员工复用若依用户”方案已废弃。当前实现与验收以
> `M15-门店员工小程序.md` 和 `M13-全局枚举与接口契约.md` 为准。

## 最终决策

1. 新建独立门店员工主表 `shop_staff`，保存员工账号、姓名、唯一手机号、BCrypt 密码、状态和 `token_version`。
2. `shop_staff` 与若依管理后台 `sys_user` 完全解耦，不共享账号、密码、Token 或超级管理员身份。
3. 门店关系表 `staff_shop` 使用 `staff_id` 关联 `shop_staff.id`；只表示员工被授权操作哪些门店，不维护每店职务。
4. 员工端签发独立 JWT，每次请求校验员工状态、`token_version` 和 `staff_shop` 门店授权。
5. 管理后台通过 `/api/admin/staff` 维护独立员工，通过 `/api/admin/shop/{shopId}/staff` 维护员工与门店绑定。
6. 已有数据使用 `gogorder_v1_0_staff_independent_schema_patch.sql` 一次性迁移；迁移完成后删除旧登录映射表。

## 保留的业务决策

- 普通店员允许在制作前发起整单全额退款，但必须填写原因，并校验门店归属、订单状态和退款幂等。
- 员工小程序不做微信订阅消息、轮询、声音或振动提醒；接单提醒由 PC 看板和打印机承担。
- 首次绑定门店自动设为默认门店；多门店员工切换门店时只校验目标门店是否已授权。
