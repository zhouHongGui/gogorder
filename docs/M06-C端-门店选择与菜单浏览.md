# M06 - C端门店选择与菜单浏览

---

## 1. 概述

C端用户进入后先选择门店，再浏览该门店的菜单（多分类商品列表 + 规格选择）。门店ID是全局上下文，影响后续所有操作。

**所属端**：C端（uni-app）+ 后端

**优先级**：🔴 高 — M07/M08 的前置

---

## 2. 功能列表

| 编号 | 功能 |
|------|------|
| F01 | 获取位置 + 附近门店（含跨午夜营业判断） |
| F02 | 门店搜索 + 详情 |
| F03 | 选择/切换门店（全局上下文更新） |
| F04 | 多分类商品列表 + 搜索 |
| F05 | 商品详情 + 规格选择（传 optionId） |

---

## 3. 设计逻辑

### 3.1 门店可见性（对齐 M13）

所有 `del_flag=0` 的门店在C端可见。`RESTING`/`PAUSED` 展示对应标签，仅 `OPEN` 可进入菜单下单。

### 3.2 营业时间判断（含跨午夜）

后端在返回门店列表时，额外返回 `isOpen` 布尔字段，由服务端计算当前是否在营业时间内。

### 3.3 商品多分类

```
GET /api/c/product/list?shopId=1
→ 返回该门店所有上架商品 + 所属分类列表
```

商品通过 `product_category` 关联表支持多分类。同一商品可能出现在多个分类下。返回结构中 `categories` 字段为数组。

### 3.4 规格选择（optionId）

商品详情中的规格选项返回：
```json
{
  "specs": [
    {
      "templateId": 1,
      "name": "杯型",
      "type": 1,
      "options": [
        {"optionId": "opt_abc123", "label": "中杯", "priceAdd": 0, "isDefault": true},
        {"optionId": "opt_def456", "label": "大杯", "priceAdd": 300, "isDefault": false}
      ]
    }
  ]
}
```

前端选择后传递给购物车/下单的数据格式：
```json
{
  "specs": {
    "1": "opt_def456",       // 模板ID: optionId（单选）
    "5": ["opt_jkl012", "opt_mno345"]  // 多选规格传数组
  }
}
```

价格由后端根据 optionId 重新计算，前端不传递价格。

### 3.5 展示价计算

展示价 = min(该门店该商品所有规格组合中的最低可能价格) = base_price + 所有默认选项的 priceAdd。

## 4. 接口定义

### 4.1 附近门店

```
GET /api/c/shop/nearby?longitude=113.32&latitude=23.12
```

响应含 `distance`(米)、`isOpen`(bool)。

### 4.2 商品分类（按门店）

```
GET /api/c/category/list?shopId=1
```

仅返回该门店在售商品所属的分类（去重）。

### 4.3 商品列表

```
GET /api/c/product/list?shopId=1&categoryId=2
```

响应中每个商品含 `categories` 数组（多分类）。

### 4.4 商品详情（含规格）

```
GET /api/c/product/{id}?shopId=1
```

返回完整规格选项（含 optionId + priceAdd）。
