# M12 - 消息推送

---

## 1. 概述

在关键节点向C端用户推送消息通知。小程序使用**微信订阅消息**，H5可后续扩展短信或App内通知。V1.0 余额支付无微信支付回调流程，消息推送聚焦在订单状态变更通知。

**所属端**：后端

**优先级**：🟢 低 — 核心交易闭环不依赖推送，可最后实现

---

## 2. 推送场景

| 触发时机 | 消息 | 优先级 |
|----------|------|--------|
| 支付成功 | 下单成功通知 | 高 |
| 制作完成 | 取餐提醒（含取餐号） | 高 |

---

## 3. 设计逻辑

### 3.1 小程序订阅消息

- 前端下单前引导用户授权订阅消息（`wx.requestSubscribeMessage`）。
- 触发时后端调用微信 `subscribeMessage.send` 接口。
- access_token 缓存 Redis（TTL 7000秒）。

### 3.2 异步发送

推送不阻塞主流程：
```
支付成功/制作完成
  ├── 更新订单状态 → 成功返回
  └── @Async 发送订阅消息
        ├── 成功 → 记录日志
        └── 失败 → 记录错误日志（不影响主流程）
```

### 3.3 H5 端

H5 端不依赖公众号模板消息（V1.0 H5 用户可能未关注公众号）。可后续扩展短信通知。

---

## 4. 集成点

| 触发位置 | 模块 | 推送 |
|----------|------|------|
| 余额支付成功 | M08 | `sendOrderPlacedNotice` |
| 制作完成 | M10 | `sendPickupReadyNotice` |

---

## 5. 前置依赖
- M05 - 用户登录（c_user_wechat 需存储小程序 openid）
- M08 - 下单支付
- M10 - 门店端

## 6. 验收标准
- [ ] 小程序授权订阅后，支付成功收到服务通知
- [ ] 制作完成后收到取餐提醒
- [ ] 未授权时不推送不报错
- [ ] 推送失败不阻塞订单流转
- [ ] access_token 自动刷新正常
