# M08 - C端下单与余额支付

---

## 1. 概述

C端用户确认购物车后提交订单，使用**余额支付**完成付款。本模块是交易闭环的核心——从购物车到订单到支付完成。

**所属端**：C端（uni-app）+ 后端

**优先级**：🔴 最高 — V1.0 MVP 核心目标

---

## 2. 功能列表

| 编号 | 功能 |
|------|------|
| F01 | 订单确认页（展示明细 + 金额） |
| F02 | 提交即时单/预订单（校验 + 创建 + 原子扣库存） |
| F03 | 余额支付（原子扣款 + 幂等） |
| F04 | 支付超时自动取消（Quartz） |
| F05 | 用户取消未支付订单 |

## 3. 设计逻辑

### 3.1 下单流程

```
1. 用户点击"提交订单"，携带全局唯一 `submitToken`
2. 后端先按 `userId + submitToken` 检查重复提交；已存在则返回原订单
3. 后端校验：订单类型对应的门店状态、预订单取餐时间（含跨午夜）、商品上架、规格必选/多选规则、库存充足、价格一致
4. 在同一事务中创建 biz_order（order_status=0, pay_status=0）
   + biz_order_item（规格 optionId + label + priceAdd 完整快照）
   + 原子扣减库存（每个订单商品使用独立 stock_ledger 幂等键）
5. 返回订单信息
6. 用户确认 → 调余额支付接口
```

### 3.2 余额支付流程（对齐 M13）

```
POST /api/c/order/pay/{orderId}
      │
      ▼
1. 幂等检查：payment_ledger.idempotent_key = "{orderId}:pay"
   已存在 → 直接返回成功（幂等）
      │
      ▼
2. 校验：order_status=0, pay_status=0
      │
      ▼
3. 开启事务：
   a. SELECT * FROM biz_order WHERE id = ? FOR UPDATE，校验订单归属和待支付状态
   b. SELECT * FROM c_user_balance WHERE user_id = ? FOR UPDATE（行级锁）
   c. 校验 balance >= total_amount → 不足返回"余额不足"
   d. UPDATE SET balance = balance - amount, version = version + 1
   e. INSERT balance_ledger（type=PAY, amount=-total_amount）
   f. INSERT payment_ledger（idempotent_key="{orderId}:pay"）
   g. UPDATE biz_order SET order_status=1, pay_status=1, pay_time=NOW(), accept_time=NOW()（支付成功即自动接单）
   h. 生成 pickup_token + pickup_date + pickup_display
   i. 提交事务
      │
      ▼
4. 异步：发送订阅消息/模板消息（M12）
```

**并发防护**：
- 余额：行级锁 `FOR UPDATE` + 乐观锁 `version`
- 支付幂等：`payment_ledger.uk_idempotent` 唯一约束
- 同一订单不允许并发支付
- 支付、取消和超时任务必须锁定订单行，或使用带原状态条件的原子 UPDATE。

### 3.3 即时单与预订单

- `NORMAL` 即时单：仅门店 `OPEN` 且当前处于营业时段时可提交。
- `PREORDER` 预订单：必须携带 `scheduledPickupTime`，符合门店预约范围配置，并落在门店营业时段内。
- `RESTING` / `PAUSED` 门店只能提交预订单。
- 两种订单支付成功后都自动进入 `ACCEPTED`。预订单在门店端按预约取餐时间排序展示。

### 3.4 余额不足处理

```json
{ "code": 400, "msg": "余额不足", "data": { "balance": 3000, "required": 6400 } }
```

前端提示用户"余额不足，请联系店员充值"。V1.0 C端无充值入口，充值由管理员在后台手动操作。

### 3.5 充值（V1.0 仅后台手动）

- C端无充值 UI。
- 管理员在后台为用户手动增加余额 → 写入 `balance_ledger`（type=RECHARGE）。
- 不经过支付网关。

### 3.6 库存扣减（对齐 M13）

```sql
UPDATE shop_product
SET stock = CASE WHEN stock = -1 THEN -1 ELSE stock - #{quantity} END
WHERE id = #{id}
  AND (stock = -1 OR stock >= #{quantity});
-- 影响行数 = 0 → 库存不足
```

每个订单商品写入独立 `stock_ledger`，幂等键 `{orderId}:{shopProductId}:DEDUCT` 防止重复扣减。

### 3.7 支付超时取消（Quartz）

每分钟扫描：
```sql
SELECT * FROM biz_order
WHERE order_status = 0 AND pay_status = 0
  AND create_time < DATE_SUB(NOW(), INTERVAL 15 MINUTE)
```

处理：使用带状态条件的原子更新将订单改为 `order_status=5, pay_status=2` → 按订单商品恢复有限库存（幂等键 `{orderId}:{shopProductId}:RESTORE`）。

### 3.8 取消与退款

- `order_status=0` → 直接取消，恢复库存。
- 用户支付后不允许主动取消。
- 已支付且尚未开始制作的订单，只允许管理员或门店取消，并且每单仅允许一次整单全额退款。

## 4. 接口定义

### 4.1 提交订单

```
POST /api/c/order/submit
Body: {
  "shopId": 1,
  "submitToken": "uuid",
  "orderType": "NORMAL",
  "scheduledPickupTime": null,
  "remark": "...",
  "items": [
    {
      "productId": 10,
      "specs": {"1": "opt_def456", "2": "opt_ghi001", "5": ["opt_mno003"]},
      "quantity": 2
    }
  ]
}
```

响应：
```json
{
  "code": 200,
  "data": {
    "orderId": 1,
    "orderNo": "20260607143215829301",
    "totalAmount": 6400,
    "balance": 50000,
    "createTime": "..."
  }
}
```

### 4.2 余额支付

```
POST /api/c/order/pay/{orderId}
Body: {}  (无额外参数，支付金额由后端从订单取)
```

响应：
```json
{
  "code": 200,
  "msg": "支付成功",
  "data": {
    "orderNo": "20260607143215829301",
    "pickupDisplay": "00012",
    "balanceAfter": 43600
  }
}
```

错误：
```json
{ "code": 400, "msg": "余额不足", "data": { "balance": 3000, "required": 6400 } }
{ "code": 409, "msg": "订单已支付", "data": { "payStatus": 1 } }
```

### 4.3 用户取消未支付订单

```
PUT /api/c/order/cancel/{id}
```

仅允许当前用户取消自己的 `order_status=0, pay_status=0` 订单。

## 8. 验收标准
- [ ] 下单校验全部生效（营业/上架/库存/价格）
- [ ] 重复 submitToken 返回同一订单，不重复创建订单或扣减库存
- [ ] 规格必选、多选数量、禁用选项校验生效
- [ ] 休息/暂停门店只能提交合法预约时间的预订单
- [ ] 库存原子扣减：并发下单库存不超卖
- [ ] 余额支付成功：扣款+流水+状态更新原子完成
- [ ] 余额不足返回错误，不扣款
- [ ] 支付幂等：重复支付返回成功不重复扣款
- [ ] 支付超时15分钟自动取消 + 库存恢复
- [ ] 未支付订单取消/超时后库存恢复，幂等键防重复
- [ ] 管理员或门店取消已接单订单时，全额退款、订单状态、库存恢复在同一事务完成
- [ ] 用户支付后取消请求被拒绝
- [ ] 每单只允许一次整单全额退款，不支持部分退款
- [ ] 支付流水/退款流水/库存流水 idempotent_key 唯一约束生效
- [ ] 规格快照完整（optionId + label + priceAdd）
