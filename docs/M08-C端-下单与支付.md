# M08 - C端下单与余额支付

---

## 1. 概述

C端用户确认购物车后提交订单，使用**余额支付**完成付款。本模块是交易闭环的核心——从购物车到订单到支付完成。

**所属端**：C端（uni-app）+ 后端

**优先级**：🔴 最高 — V1.0 MVP 核心目标

---

| 编号 | 功能 |
|------|------|

| F05 | 取消订单（库存恢复 + 余额退款） |

## 3. 设计逻辑

### 3.1 下单流程

```
1. 用户点击"提交订单"
2. 后端校验：门店营业（含跨午夜）、商品上架、库存充足、价格一致
3. 校验通过 → 创建 biz_order（order_status=0, pay_status=0）
   + biz_order_item（规格 optionId + label + priceAdd 完整快照）
   + 原子扣减库存（条件 UPDATE + stock_ledger 幂等键 {orderId}:stock）
4. 返回订单信息
5. 用户确认 → 调余额支付接口
```

### 3.2 余额支付流程（对齐 M13）

```
POST /api/c/order/pay/{orderId}
      │
      ▼
1. 幂等检查：payment_ledger.idempotent_key = "{orderId}:pay"
   已存在 → 直接返回成功（幂等）
      │
      ▼
2. 校验：order_status=0, pay_status=0
      │
      ▼
3. 开启事务：
   a. SELECT * FROM c_user_balance WHERE user_id = ? FOR UPDATE（行级锁）
   b. 校验 balance >= total_amount → 不足返回"余额不足"
   c. UPDATE SET balance = balance - amount, version = version + 1
   d. INSERT balance_ledger（type=PAY, amount=-total_amount）
   e. INSERT payment_ledger（idempotent_key="{orderId}:pay"）
   f. UPDATE biz_order SET order_status=1, pay_status=1, pay_time=NOW()
   g. 生成 pickup_token + pickup_display
   h. 提交事务
      │
      ▼
4. 异步：发送订阅消息/模板消息（M12）
```

**并发防护**：
- 余额：行级锁 `FOR UPDATE` + 乐观锁 `version`
- 支付幂等：`payment_ledger.uk_idempotent` 唯一约束
- 同一订单不允许并发支付

### 3.3 余额不足处理

```json
{ "code": 400, "msg": "余额不足", "data": { "balance": 3000, "required": 6400 } }
```

前端提示用户余额不足并引导充值（V1.0 充值功能可先做后台手动充值）。

### 3.4 库存扣减（对齐 M13）

```sql
UPDATE shop_product
SET stock = stock - #{quantity}
WHERE id = #{id}
  AND stock >= #{quantity}
  AND stock > 0;
-- 影响行数 = 0 → 库存不足
```

同时写入 `stock_ledger`，幂等键 `{orderId}:stock` 防止重复扣减。

### 3.5 支付超时取消（Quartz）

每分钟扫描：
```sql
SELECT * FROM biz_order
WHERE order_status = 0 AND pay_status = 0
  AND create_time < DATE_SUB(NOW(), INTERVAL 15 MINUTE)
```

处理：更新 `order_status=5, pay_status=2` → 恢复库存（幂等键防重）。

### 3.6 用户主动取消

- `order_status=0` → 直接取消，恢复库存。
- `order_status=1, pay_status=1` → 取消 + 退款（恢复余额 + 恢复库存，幂等键防重）。

## 4. 接口定义

### 4.1 提交订单

```
POST /api/c/order/submit
Body: {
  "shopId": 1,
  "remark": "...",
  "items": [
    {
      "productId": 10,
      "specs": {"1": "opt_def456", "2": "opt_ghi001", "5": ["opt_mno003"]},
      "quantity": 2
    }
  ]
}
```

响应：
```json
{
  "code": 200,
  "data": {
    "orderId": 1,
    "orderNo": "20260607143215829301",
    "totalAmount": 6400,
    "balance": 50000,
    "createTime": "..."
  }
}
```

### 4.2 余额支付

```
POST /api/c/order/pay/{orderId}
Body: {}  (无额外参数，支付金额由后端从订单取)
```

响应：
```json
{
  "code": 200,
  "msg": "支付成功",
  "data": {
    "orderNo": "20260607143215829301",
    "pickupDisplay": "00012",
    "balanceAfter": 43600
  }
}
```

错误：
```json
{ "code": 400, "msg": "余额不足", "data": { "balance": 3000, "required": 6400 } }
{ "code": 409, "msg": "订单已支付", "data": { "payStatus": 1 } }
```

### 4.3 取消订单

```
PUT /api/c/order/cancel/{id}
```

| stock_ledger | INSERT（幂等键） |

## 8. 验收标准
- [ ] 下单校验全部生效（营业/上架/库存/价格）
- [ ] 库存原子扣减：并发下单库存不超卖
- [ ] 余额支付成功：扣款+流水+状态更新原子完成
- [ ] 余额不足返回错误，不扣款
- [ ] 支付幂等：重复支付返回成功不重复扣款
- [ ] 支付超时15分钟自动取消 + 库存恢复
- [ ] 取消订单：库存恢复 + 余额退款，幂等键防重复
- [ ] 支付流水/退款流水/库存流水 idempotent_key 唯一约束生效
- [ ] 规格快照完整（optionId + label + priceAdd）
