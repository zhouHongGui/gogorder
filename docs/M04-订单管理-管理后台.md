# M04 - 订单管理（管理后台）

---

## 1. 概述

平台管理员查看全平台订单，支持多条件筛选、查看详情、取消并退款。本模块与 B端看板（M10）共享同一份订单数据但操作视角不同。

**所属端**：管理后台（Vue 3 + Vite 6）+ 后端

**优先级**：🟡 中 — 依赖订单数据产生（M08）

---

## 2. 功能列表

| 编号 | 功能 |
|------|------|
| F01 | 订单列表（分页 + 多条件筛选） |
| F02 | 订单详情（含三状态 + 时间线） |
| F03 | 取消订单（已支付订单仅支持一次整单全额退款） |

---

## 3. 设计逻辑

### 3.1 订单三状态（对齐 M13）

| 字段 | 含义 | 取值 |
|------|------|------|
| `order_status` | 业务履约 | 0-5 |
| `pay_status` | 支付 | 0-4 |
| `refund_status` | 退款 | 0-3 |

列表展示时合并展示主要状态，详情展示三字段分别显示。

### 3.2 取消订单规则

| 条件 | 允许取消 | 退款 |
|------|----------|------|
| `order_status=0` | ✅ | 无需（未支付） |
| `order_status=1, pay_status=1` | ✅ | 每单一次整单全额退款 |
| `order_status>=2` | ❌ | — |

取消已支付订单必须在同一数据库事务内完成：
1. `SELECT biz_order ... FOR UPDATE`，校验仍为 `order_status=1, pay_status=1, refund_status=0`
2. 锁定余额账户并全额恢复余额
3. 写入 `refund_ledger`、`balance_ledger` 和每个订单商品的库存恢复流水
4. 恢复有限库存
5. 更新 `order_status=5`、`pay_status=4`、`refund_status=2`
6. 任一步失败则整笔事务回滚

V1.0 不支持部分退款。退款金额必须等于订单 `total_amount`，且同一订单最多成功退款一次。

### 3.3 筛选维度

订单号、门店、order_status、pay_status、日期范围、手机号。

---

## 4. 接口定义

### 4.1 订单列表

```
GET /api/admin/order/list
```

参数：`pageNum`, `pageSize`, `orderNo`, `shopId`, `orderStatus`, `payStatus`, `startTime`, `endTime`, `phone`

响应（若依分页格式）：`{ rows: [...], total: 156 }`

### 4.2 订单详情

```
GET /api/admin/order/{id}
```

返回：基本信息 + 三状态时间线 + 商品明细 + 金额 + 支付流水 + 退款流水（如有）。

### 4.3 取消订单

```
PUT /api/admin/order/{id}/cancel
Body: { "reason": "门店无法履约" }
```

校验 order_status=0 或 (order_status=1 且 pay_status=1) → 取消；已支付订单执行一次整单全额退款。
